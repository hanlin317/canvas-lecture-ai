# macOS 0.6.0 launch repair

_Updated: 1 November 2026_

## Purpose

Repair the macOS launch regression in release 0.6.0 and the bundled FFmpeg lookup used by local
MLX Whisper transcription. The repair is delivered as 0.7.0 because published releases are
immutable.

## Diagnosis

- The installed 0.6.0 Apple Silicon application exited before starting its local server.
- Direct launch reported that `Python.framework` could not load because hardened runtime library
  validation found different Team IDs between the process and embedded framework.
- The 0.6.0 build added `--options runtime` to an ad-hoc signature. Version 0.5.0 used plain ad-hoc
  signing and launched successfully.
- Application logs also showed MLX Whisper failing to find the literal `ffmpeg` command even though
  an architecture-specific FFmpeg executable was bundled.

## Changes

- Unsigned macOS packages now use plain ad-hoc signing. Hardened runtime and secure timestamping are
  applied only when a real Developer ID identity is configured.
- The macOS package includes a stable `ffmpeg` link, and packaged startup exposes the bundled binary
  through `DLM_FFMPEG`, `IMAGEIO_FFMPEG_EXE`, and `PATH`.
- The release workflow now launches the packaged application with isolated data and waits for its
  local HTTP server, in addition to running the existing self-check.
- Focused runtime tests cover the packaged FFmpeg environment.

- `ruff check app tests scripts/2026-10-26-release-notes.py` passed.
- `pytest -q` passed all 84 tests.
- `git diff --check` passed, and the GitHub Actions workflow parsed successfully as YAML.
- The local Apple Silicon 0.7.0 package built successfully through the supported build script.
- The packaged self-check reported MLX Whisper, Word, Markdown, ReportLab, FFmpeg, and Playwright

- The application launched successfully from the mounted DMG with isolated data.

## Rollback

All source changes are isolated on branch `codex/macos-launch-fix` and can be reverted through Git.
The published 0.5.0 and 0.6.0 release assets remain unchanged.

## Known limitations

- Without configured Apple Developer ID credentials, macOS packages remain ad-hoc signed and are
  not notarized; users may still need the Finder right-click **Open** flow on first launch.
- The local verification covered Apple Silicon. Intel macOS and Windows packages are validated by
  the release workflow on their native GitHub-hosted runners.
- The current macOS tooling warns that the existing `hdiutil` image commands are deprecated on the
  newest macOS release. They remain supported by the macOS 14 and 15 release runners and were not
  changed as part of this launch repair.
